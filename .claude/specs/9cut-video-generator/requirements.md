# 9Cut 口播视频自动生成系统 - 需求规格说明书

## 1. 项目概述

9Cut是一个基于Vue 3 + Node.js + SQLite的纯前端口播视频自动生成系统，通过nginx部署。系统支持从文案自动生成分镜脚本，每9个分镜组成一组剧情连贯的9宫格，自动生成图片、视频和语音，最终合成完整的口播视频。系统支持多种AI服务集成，提供灵活的提示词管理和内容重新生成功能。

---

## 2. 功能需求

### 2.1 项目管理

**用户故事**: 作为内容创作者，我希望能够创建和管理多个视频项目，以便组织不同的口播视频内容。

**验收标准**:
1. 当用户创建新项目时，系统应允许输入项目名称和描述
2. 当项目创建成功时，系统应自动生成唯一的项目ID
3. 当用户查看项目列表时，系统应显示所有项目及其状态（草稿/处理中/已完成）
4. 当用户删除项目时，系统应同时删除所有关联的资源文件
5. 当用户编辑项目时，系统应允许修改项目名称和描述

### 2.2 文案输入与管理

**用户故事**: 作为内容创作者，我希望能够输入和编辑口播文案，以便系统能够根据文案生成分镜。

**验收标准**:
1. 当用户输入文案时，系统应支持多段落的文本输入
2. 当文案输入完成时，系统应自动保存到数据库
3. 当用户编辑文案时，系统应实时更新并标记关联内容需要重新生成
4. 当文案长度超过限制时，系统应提示用户并支持自动分割
5. 当用户导入文案时，系统应支持从txt、docx文件导入

### 2.3 文生分镜

**用户故事**: 作为内容创作者，我希望系统能够自动将文案转换为分镜脚本，以便生成结构化的视频内容。

**验收标准**:
1. 当用户触发分镜生成时，系统应调用配置的AI服务生成分镜
2. 当分镜生成完成时，系统应生成包含场景描述、画面说明、预计时长的分镜脚本
3. 当分镜数量不是9的倍数时，系统应自动补充或提示用户调整
4. 当用户编辑分镜时，系统应支持手动调整分镜内容
5. 当用户重新生成分镜时，系统应使用当前生效的提示词和AI服务
6. 当生成失败时，系统应显示错误信息并允许重试

### 2.4 9宫格分组管理

**用户故事**: 作为内容创作者，我希望每9个分镜自动组成一组剧情连贯的9宫格，以便生成有节奏感的视频内容。

**验收标准**:
1. 当分镜生成完成时，系统应自动将分镜按每9个一组进行分组
2. 当查看分组时，系统应以9宫格布局展示每组分镜
3. 当分镜数量不足9个时，系统应支持占位显示或自动补充
4. 当用户调整分镜顺序时，系统应自动更新分组
5. 当用户查看分组详情时，系统应显示该组所有分镜的状态和资源

### 2.5 分镜图片生成

**用户故事**: 作为内容创作者，我希望系统能够为每个分镜自动生成图片，上一个分镜的尾帧作为当前分镜的首帧。

**验收标准**:
1. 当触发图片生成时，系统应为每个分镜生成尾帧图片
2. 当图片生成完成时，系统应自动将上一个分镜的尾帧设置为当前分镜的首帧
3. 当第一个分镜生成时，系统应生成独立的首帧图片
4. 当用户重新生成单个分镜图片时，系统应更新该分镜及后续分镜的首尾帧关联
5. 当图片生成失败时，系统应允许单独重新生成失败的图片
6. 当图片生成完成时，系统应支持预览和下载

### 2.6 自动切图与挂载

**用户故事**: 作为内容创作者，我希望系统能够自动处理生成的图片并挂载到对应分镜，以便后续视频生成。

**验收标准**:
1. 当图片生成完成时，系统应自动进行图片尺寸标准化处理
2. 当切图完成时，系统应自动关联到对应的分镜记录
3. 当查看分镜时，系统应显示已挂载的首帧和尾帧图片
4. 当图片更新时，系统应自动更新挂载关系
5. 当导入外部图片时，系统应支持手动挂载到指定分镜

### 2.7 分镜视频生成

**用户故事**: 作为内容创作者，我希望系统能够根据分镜内容和首尾帧图片生成单个分镜的视频。

**验收标准**:
1. 当触发视频生成时，系统应使用首帧和尾帧图片生成过渡视频
2. 当视频生成时，系统应根据分镜描述添加动效（如平移、缩放、淡入淡出）
3. 当视频生成完成时，系统应按预设的分镜时长生成对应长度的视频
4. 当用户调整时长时，系统应支持重新生成指定时长的视频
5. 当视频生成失败时，系统应显示错误原因并允许重试
6. 当视频生成完成时，系统应支持预览和下载

### 2.8 视频合并

**用户故事**: 作为内容创作者，我希望系统能够将多个分镜视频按序号合并成一组连贯的视频。

**验收标准**:
1. 当触发合并时，系统应按分镜序号顺序合并视频
2. 当合并完成时，系统应生成流畅无缝的完整视频
3. 当部分分镜视频缺失时，系统应提示用户并显示缺失列表
4. 当用户选择部分合并时，系统应支持选择性合并指定分镜
5. 当合并完成时，系统应支持预览和下载最终视频

### 2.9 口播文案生成

**用户故事**: 作为内容创作者，我希望系统能够根据原始文案生成适合口播的文案。

**验收标准**:
1. 当触发口播文案生成时，系统应调用AI服务生成口语化的文案
2. 当生成完成时，系统应输出适合朗读的口播文案
3. 当用户编辑口播文案时，系统应支持手动调整
4. 当用户重新生成时，系统应使用当前生效的提示词
5. 当生成失败时，系统应显示错误信息并允许重试

### 2.10 口播文案拆分

**用户故事**: 作为内容创作者，我希望系统能够根据分镜和时长自动拆分口播文案，以便与视频节奏匹配。

**验收标准**:
1. 当触发拆分时，系统应根据分镜数量和时长拆分口播文案
2. 当拆分完成时，每个分镜应关联对应的口播文案片段
3. 当分镜时长调整时，系统应支持重新拆分文案
4. 当用户手动调整拆分点时，系统应支持拖拽调整
5. 当拆分后文案与分镜不匹配时，系统应提示用户

### 2.11 语音生成

**用户故事**: 作为内容创作者，我希望系统能够根据口播文案生成语音文件。

**验收标准**:
1. 当触发语音生成时，系统应调用TTS服务生成语音
2. 当生成完成时，系统应为每个分镜生成对应的语音片段
3. 当用户选择语音角色时，系统应支持多种音色选择
4. 当用户调整语速时，系统应支持语速参数配置
5. 当用户重新生成时，系统应支持单个语音片段重新生成
6. 当语音生成完成时，系统应支持预览和下载

### 2.12 AI服务配置

**用户故事**: 作为系统管理员，我希望能够配置多种AI服务，以便灵活选择最适合的服务提供商。

**验收标准**:
1. 当配置AI服务时，系统应支持Claude、Gemini、OpenAI、火山引擎、千问等服务
2. 当配置服务时，系统应允许输入API密钥、端点地址、模型名称
3. 当多个服务配置时，系统应支持为每个功能选择不同的服务
4. 当切换服务时，系统应只有一套配置生效
5. 当服务不可用时，系统应显示连接状态并允许测试连接
6. 当配置更新时，系统应即时生效无需重启

### 2.13 提示词管理

**用户故事**: 作为内容创作者，我希望能够为每个功能配置多个提示词模板，以便根据需要切换。

**验收标准**:
1. 当配置提示词时，系统应支持为每个功能创建多个提示词模板
2. 当使用提示词时，系统应只有一个提示词处于生效状态
3. 当创建提示词时，系统应支持变量占位符（如{文案}、{分镜描述}）
4. 当切换提示词时，系统应立即生效
5. 当删除提示词时，系统应检查是否为当前生效的提示词
6. 当导入导出时，系统应支持提示词模板的导入导出

### 2.14 重新生成功能

**用户故事**: 作为内容创作者，我希望能够重新生成任意环节的内容，以便迭代优化生成结果。

**验收标准**:
1. 当用户选择重新生成时，系统应支持重新生成单个分镜的所有内容
2. 当用户选择重新生成时，系统应支持只重新生成特定类型的内容（如只重新生成图片）
3. 当重新生成时，系统应保留历史版本供对比
4. 当重新生成完成时，系统应自动更新相关联的内容
5. 当批量重新生成时，系统应显示进度和状态

### 2.15 资源管理

**用户故事**: 作为内容创作者，我希望能够管理所有生成的资源文件，以便查看和导出。

**验收标准**:
1. 当查看资源时，系统应分类显示图片、视频、音频文件
2. 当下载资源时，系统应支持单个和批量下载
3. 当删除资源时，系统应更新关联的分镜状态
4. 当存储空间不足时，系统应提示用户清理历史资源
5. 当导出项目时，系统应支持打包导出所有资源

---

## 3. 非功能需求

### 3.1 性能需求

1. 页面加载时间应在3秒内完成
2. 分镜生成响应时间应在30秒内（依赖AI服务）
3. 图片生成应支持并行处理，提升效率
4. 视频合并应在1分钟内完成（10个分镜以内）
5. 系统应支持同时处理5个以上的生成任务

### 3.2 可用性需求

1. 界面应响应式设计，支持桌面端和平板端
2. 所有操作应有明确的状态反馈
3. 错误信息应清晰明了，提供解决建议
4. 应支持操作撤销和重做
5. 应提供操作引导和帮助文档

### 3.3 安全需求

1. API密钥应加密存储
2. 用户上传的文件应进行安全校验
3. 应防止XSS和CSRF攻击
4. 敏感操作应有确认提示

### 3.4 兼容性需求

1. 支持Chrome、Firefox、Safari、Edge最新版本
2. 支持nginx反向代理部署
3. 前端应支持静态资源CDN加速
4. 应支持通过环境变量配置服务地址

---

## 4. 数据需求

### 4.1 项目数据

- 项目ID、名称、描述、状态、创建时间、更新时间

### 4.2 分镜数据

- 分镜ID、项目ID、序号、场景描述、画面说明、时长、首帧图片ID、尾帧图片ID、视频ID、口播文案、语音ID

### 4.3 资源数据

- 资源ID、类型（图片/视频/音频）、文件路径、文件大小、创建时间、关联分镜ID

### 4.4 AI服务配置数据

- 配置ID、服务类型、功能类型、API密钥、端点地址、模型名称、是否启用

### 4.5 提示词数据

- 提示词ID、功能类型、模板名称、模板内容、是否生效、创建时间

---

## 5. 接口需求

### 5.1 AI服务接口

- 文本生成接口（分镜生成、口播文案生成）
- 图片生成接口（分镜图片生成）
- 语音合成接口（TTS服务）
- 视频生成接口（图生视频）

### 5.2 内部API接口

- 项目CRUD接口
- 分镜CRUD接口
- 资源管理接口
- 配置管理接口
- 提示词管理接口
- 生成任务接口

---

## 6. 约束条件

1. 技术栈：Vue 3 + Node.js + SQLite
2. 部署方式：nginx静态部署 + 后端API服务
3. 存储方式：本地文件存储 + SQLite数据库
4. AI服务：依赖第三方API服务
5. 浏览器：现代浏览器（不支持IE）
